# TSLA спред-монитор: Lighter (шорт) ↔ Jupiter (TSLAx)

Подсказывает, когда выгодно закрывать дельта-нейтральную позицию порциями:
**выкупить шорт TSLA на Lighter (Robinhood chain)** и **продать TSLAx на Jupiter**.

```
спред на акцию = (USDC за продажу N TSLAx на Jupiter) / N  −  средняя цена выкупа N TSLA по стакану Lighter
```
Если спред больше нуля, закрывать порцию N сейчас выгодно. Он считается для порций 1, 2, 3, 5, 10 и 24 шт с учётом глубины стакана и проскальзывания.

## Установка — одна команда

```bash
curl -fsSL https://raw.githubusercontent.com/Kinbas-validator/TSLA/main/install.sh | sudo bash
```

Установщик спросит пароль для веб-интерфейса, токен Telegram-бота и порог. В конце покажет **https-адрес** и пароль.

## Удаление — одна команда

```bash
sudo tsla-spread uninstall
```
Удаляются сервис, файлы, история, настройки, блок в Caddy или nginx, сертификат, правила ufw, туннель. Caddy удаляется только в том случае, если его ставил сам установщик.

## Как установщик уживается с другим софтом на сервере

1. Приложение слушает **только 127.0.0.1** на первом свободном порту, начиная с 18090. Наружу ничего не открывается, занятые порты не трогаются.
2. Домен бесплатный: `tsla-<ваш-ip>.sslip.io`, он сразу указывает на IP сервера. Свой домен можно передать так: `DOMAIN=...`.
3. Установщик смотрит, кто занимает порты 80 и 443:
   - **Caddy** (systemd + Caddyfile): в конец Caddyfile дописывается один блок для нашего домена между маркерами. Перед этим делается бэкап, после — `caddy validate` и `reload`. При ошибке файл откатывается. Остальные сайты не меняются.
   - **nginx**: добавляется отдельный `server` только для нашего домена и выпускается сертификат через certbot.
   - **ничего**: ставится Caddy с автоматическим HTTPS.
   - **что-то другое** (Docker, Apache, Traefik…): установщик туда не вмешивается и поднимает **Cloudflare Quick Tunnel** (`https://*.trycloudflare.com`). Открытые порты для этого не нужны. Адрес меняется при перезапуске, новый бот присылает в Telegram.
4. Если HTTPS по домену не заработал за 2,5 минуты (провайдер закрыл порты или Let's Encrypt упёрся в лимит), изменения в прокси откатываются и включается туннель.

Режим можно выбрать вручную: `curl … | sudo MODE=tunnel bash` (варианты: `auto`, `caddy`, `nginx`, `tunnel`).

## Telegram

1. В @BotFather выполните `/newbot` и получите токен. Его можно ввести при установке или позже через `sudo tsla-spread config`.
2. Откройте бота и отправьте `/start`, чат привяжется сам. Сообщения из чужих чатов бот игнорирует.

Бот присылает три вида сообщений:
- когда спред выбранной порции достиг порога (повтор не чаще кулдауна);
- когда спред ушёл ниже порога;
- когда пропали данные.

Команды: `/status`, `/set 0.5` (порог $/акц), `/size 5`, `/cooldown 15`, `/on`, `/off`.

## Управление

```bash
sudo tsla-spread status     # состояние и адрес
sudo tsla-spread url        # текущий https-адрес
sudo tsla-spread logs       # логи
sudo tsla-spread config     # правка настроек + перезапуск
sudo tsla-spread password   # сменить пароль веба
sudo tsla-spread update     # обновиться из GitHub (настройки и история сохраняются)
sudo tsla-spread uninstall  # удалить всё
```

## Что учтено и что нет

- Taker-комиссия Lighter на TSLA сейчас 0%. Если изменится, задаётся через `LIGHTER_TAKER_FEE` в конфиге.
- Котировка Jupiter Ultra уже учитывает комиссию Jupiter. Газ Solana не учитывается.
- Funding по шорту не учитывается.
- Котировка не гарантирует исполнение по этой цене.

## Устройство

`app/app.py` — сборщик данных, веб-сервер и Telegram-бот на чистом Python 3, без pip-зависимостей. Данные хранятся в SQLite (60 дней), памяти уходит около 30 МБ.
`app/index.html`, `app/login.html` — интерфейс (графики на uPlot).
`install.sh` — установка, удаление и управление.

Локальный запуск: `WEB_PASSWORD=test DB_PATH=./data.db BIND=127.0.0.1 python3 app/app.py` → http://localhost:8080
